# Task 3–4 freeze and bootstrap integrity correction

This correction binds exported predictions to their required converged projection fits and binds bootstrap intervals to the complete declared bootstrap run. It changes artifact integrity checks, not the demographic models, optimization settings, simulation calibration, or scientific acceptance thresholds. It does not establish empirical interval coverage or make either challenge scientifically ready for submission.

## Reproduced defects and corrected behavior

Against merged source `471cd8d8be8b3c43cc67b1dc50e3d40add4e98a2`, synthetic entrypoint checks demonstrated that the Task 3 and Task 4 freeze wrappers accepted a cached projection median inconsistent with the contributing fits. They also accepted nonfinite interval bounds, allowing a `NaN` token in the output JSON. The narrow correction independently reviewed before the bootstrap extension recomputes the median from the complete required projection set, requires the existing selected-optimizer convergence gate for every contributing fit, and rejects a cached median that differs beyond floating-point serialization tolerance. It never drops an unsuccessful projection and recomputes from the remaining subset.

Interval validation requires the documented parameter names, both quantile bounds, finite numeric values, ordering, and the existing physical domains. Growth timing is positive and the growth ratio exceeds one. Split sizes and timing are positive. A migration interval may include zero, while the existing positive point-fit and numerical relative-change policies remain unchanged. Strict atomic JSON writing prevents a validation or serialization failure from leaving a partial artifact.

The adjacent bootstrap defect was an undeclared denominator: summaries could calculate intervals from the files that happened to be present, without proving that every planned replica existed or that its selected optimum converged. The new `demography_linked_bootstrap_v1` contract records the total and exact integer IDs before fitting, input hashes, producer/model/supporting-source hashes, numerical and resampling settings, and runtime package versions. Every shard must carry the same contract. Runtime versions are recorded and must agree across shards; summary execution need not use identical package versions.

Each producer writes a running checkpoint and retains every attempted replica, including finite but unconverged fits and exceptions. Retained restart diagnostics must contain the complete requested restart IDs. The selected restart must be the actual best finite retained likelihood, and its own convergence flag and optimizer status must agree; a worse converged restart cannot replace a better unconverged fit to authorize intervals. Input hashes are checked before and after reading and again after fitting. A changed input fails the task while preserving its attempted-fit records.

Independent review of the first frozen patch reproduced an additional arithmetic inconsistency: changing a retained replica's physical timing by a factor of ten while keeping theta, scaled parameters, likelihood, and convergence fixed changed its exported interval. The second frozen patch binds top-level theta to the selected restart's retained theta and verifies ancestral size as `theta / (4 * mutation_rate * sequence_length)`. It then checks growth timing and modern size, or both split population sizes, split timing, and migration rate, against their retained scaled parameters. All inputs and derived quantities must be finite and in their existing positive domains; invalid or unrepresentable arithmetic fails the replica. A relative tolerance of `1e-12` accommodates arithmetic serialization, not scientific recovery error. The current fitters omit each restart's parameter array from public diagnostics, so these checks establish retained-theta and scaled-to-physical consistency, not full selected-endpoint parameter provenance or a recomputed model likelihood. The first patch and its independent reproduction remain preserved separately.

A follow-up review of the second frozen patch found that the arithmetic check covered bootstrap fits but not the observed projection fits. Synthetic actual-entrypoint reproductions changed reported timing and the matching cached median from 1,000 to 10,000 while holding retained theta and scaled values fixed. For Task 4, changing only the 70×50 and 94×68 projections left the 50×40 reference and its refined comparison unchanged. The third frozen patch moves the arithmetic validator into the shared freeze helper and applies it to every individual observed projection and the refined Task 4 fit, supporting both the flat and nested `fit` layouts. When observed restart diagnostics are supplied, their uniquely selected theta must also agree; arithmetic-complete historical fits without restart rows continue to follow the existing convergence policy. Missing or partially supplied arithmetic metadata is rejected, not silently skipped. The componentwise median receives only the projection/median consistency check, because nonlinear physical transforms need not commute with componentwise aggregation. Both observed-point reproductions and the prior snapshots remain preserved separately. This remains an available-field arithmetic check, not reconstruction of omitted per-restart parameter arrays or model likelihoods.

Summaries require the full unique declared replica set, completed task states, and converged selected fits. Missing, duplicate, failed, or unconverged replicas produce a failed summary with retained records and explicit counts, without interval statistics. Freeze reconstructs that summary from its retained task records, checks the top-level contract and flattened records, recomputes the quantiles, and checks the bootstrap projection, mutation rate, and growth convention against the observed fits. It exports the resulting intervals only after all existing scientific gates also pass. `interval_coverage_validated` remains explicitly false.

## Runner and regeneration contract

Both producer CLIs now require `--planned-replicates`; it is never inferred from the number of existing files. The growth Slurm wrapper derives it from the submitted contiguous zero-based array count multiplied by `REPLICATES_PER_TASK` (default 32 tasks × 4 replicas = 128). The split wrapper uses the submitted contiguous zero-based array count (default 64). Sparse and nonzero-based arrays are rejected. For an isolated retry, use a fresh producer output and explicitly preserve the original complete planned total and settings; do not shrink the denominator to the retry subset. Summarization requires every planned replica to occur exactly once among the retained task records.

Historical summaries without this contract remain unchanged and are rejected for a new freeze. Regenerate them with the current producers and complete planned run. Producers and summarizers refuse to overwrite existing output paths. A failed summary remains useful failure evidence but cannot supply intervals. Task 4's auxiliary block-design summary is retained as descriptive auxiliary information, not falsely represented as extraction provenance for the hashed block archive.

## Verification and scientific limits

The isolated second patch passed 242 focused tests in 5.01 seconds and Ruff. Both unchanged Slurm wrappers passed shell syntax checks. Tests exercise the actual producer, summarizer, and freeze entrypoints with synthetic fixtures; no new demographic optimization or simulation was performed. They include missing-prefix denominators, duplicates, malformed IDs, legacy summaries, inconsistent protocols, status spoofing, a better unconverged restart, changed inputs, corrupted statistics, nonfinite bounds, incorrect medians, retained producer exceptions, and atomic failure behavior. Additional tests reject inconsistent physical/scaled fields, selected theta mismatches, missing or invalid arithmetic inputs, and unrepresentable exposure scaling; both actual freeze mains reject the reproduced timing mutation without writing output. The prior four-file narrow patch independently passed 31 entrypoint regressions, including five valid cases with byte-identical old/new outputs. Full integration and the extended independent review are reported separately by the integrating reviewer.

The third patch passed 171 focused tests across the bootstrap-contract and freeze-entrypoint files in 1.65 seconds, plus Ruff under the repository configuration. Its additional actual-entrypoint regressions cover coordinated observed timing/median corruption, both refined-fit layouts with a mismatch smaller than the existing 1% refinement threshold, retained selected-theta disagreement, partial arithmetic metadata, preservation of existing artifacts on rejection, and arithmetic-complete historical fits without restart rows. Consistent componentwise medians with no model metadata remain accepted. No model evaluation, optimization, simulation, or production challenge inference was run for this repair; full integration and independent review of this final source are recorded separately.

These checks demonstrate artifact consistency and complete reporting, not bootstrap coverage, recovery accuracy, model adequacy, or complete upstream exposure provenance. The remaining scientific priorities are independent whole-chromosome recovery across weak and boundary regimes; Task 2 hidden-history and migration misspecification; Task 3–4 multiple independent physical-unit Q1 BGS replicates with burn-in and approximation checks; and interval coverage measured across independent complete simulated datasets. Existing scientific thresholds must be met without discarding difficult or failed cases. The already recorded recovery failures remain evidence and are not repaired by this integrity change.
