# Task 1 production optimizer repair and source replay

This change addresses a measured numerical failure; it does not establish that the two-epoch model is biologically adequate or that challenge predictions are ready to submit. The earlier independent simulation panels and all original fit outputs remain unchanged. The development sequence and all unfavorable results are preserved in `bottleneck_case08_numerics_2026_11_20.md`, `bottleneck_epsilon_extension_2026_11_20.md`, and `bottleneck_refinement_2026_11_20.md`.

## Evidence behind the fixed strategy

The isolated case 08 diagnostic identified forward finite-difference truncation bias at the old gradient step of 0.001. It did not identify a likelihood sign or population-size transformation error. A paired extension over 35 frozen spectra and 53 method problems completed all 848 original-start fits. Simply replacing the coarse step with 0.00001 was rejected: although it improved 52 of 53 selected objectives, it made the remaining moments objective worse by 14.891253. Fine-step refinement of every coarse endpoint then completed all 424 planned refinements. Retaining the complete union yielded 53/53 selected convergences and passing finite-neighborhood checks, but only 52/53 problems had two distinct starting origins agree near the best endpoint. The residual 10 Mb case 20 moments failure remains a failure.

These are repair-development results on existing spectra, not independent confirmation. The available full-length cases at the original manifest freeze were conditional on computational completion and may favor easier configurations. All selected successful optimizer terminations in that development study used relative objective reduction, not the projected-gradient stopping criterion. The finite probes cannot certify stationarity or global optimality.

## Production behavior and compatibility

Both moments and dadi now default to the versioned `paired_coarse_fine_refine_v1` strategy. Each original log-space start receives coarse (0.001) and fine (0.00001) L-BFGS-B fits; each finite coarse endpoint also receives fine-step refinement. Original starts, warm-start consumption, parameter bounds, fixed likelihood domain, and method-specific production budgets are retained. Moments uses maxfun 15000 and maxiter 500; dadi uses maxfun 500 and maxiter 15000. Other controls remain pgtol 1e-5, factr 1e7, and maxls 20. There is no derivative-free fallback or new setting search.

Selection uses the smallest finite objective regardless of convergence status. Original candidates win exact ties with later refinements. Retaining every finite coarse candidate means selection cannot degrade its best objective, although this does not guarantee convergence or accuracy. A failed refinement or optional neighborhood calculation cannot erase an already finite endpoint. Full per-arm attempts, errors, actual convergence messages, initial points, and raw neighborhood probes are retained. `successful_restarts`, `converged_restarts`, and near-best agreement count distinct original starting origins; three descendants of one origin are not three independent restarts. `legacy_coarse_v1` remains an explicit development/reproduction option. A final guard patch rejects exact duplicate original vectors, requires coarse and fine arms to retain the same original vector, and validates distinct starting vectors from saved traces before counting agreement; this closes an explicit-start API edge case without changing admitted optimizer settings.

Fit records bind the engine, strategy, optimizer controls, relevant source hashes, dependency versions, sample haplotype projection, and physical scaling. Consumer guards recompute the selected endpoint and origin agreement from retained attempts; check theta, population size, time, mutation rate, and exposure consistency; and reconstruct the 24 finite-probe displacements and maximum recorded improvement. These guards validate recorded numerical evidence, not independent evaluations of a fitted likelihood. Calibration and bootstrap consumers require compatible provenance and actual selected convergence, origin agreement, and finite-neighborhood evidence. Historical unknown optimizer identities require regeneration rather than silent mixing.

Both VCF wrappers preserve input hashes and polarization; pre/post hashing rejects changes during extraction or fitting. Bootstrap verifies the reference and VCF before parsing, after extraction, and before writing results; records the bootstrap/parser/source identities; rejects an existing output; checks projection and engine compatibility; and retains every replica's full fit and failure. Any failed replica suppresses all interval output. Successful interval output is still labeled as an unvalidated block-bootstrap coverage procedure. A known performance cost remains: the current implementation rereads the complete VCF for a full hash before each incomplete replica checkpoint, up to 200 such reads at the default replicate count; this protects the provenance checks but can add substantial I/O for large inputs.

A fifth existing 100 Mb case 16 spectrum is a separately reported stress check with the original seed 2026112951 and eight starts; it was unavailable when the previous 53-problem numerical manifest was frozen and is not added to those denominators. ## Final distinct-start guard verification

The final read-only review found that the explicit-start API accepted duplicate vectors and counted their different origin IDs toward agreement. A bounded quadratic counterexample had one distinct initial vector but two counted near-best origins. This did not affect any archived replay or development input, whose original vectors were distinct. The final guard rejects exact duplicates at both optimizer entry points and in retained trace validation; it also requires coarse and fine arms of an origin to preserve the same finite starting vector. Neither numerical settings nor optimization on distinct starts changes. The final focused suite passed 133 tests, including 26 optimizer and 41 consumer regressions; the separate read-only review addendum is `optimizer_cross_review_start_identity_addendum.json` (SHA256 `da801723339b3343c2a4a77c5d635f9814c0a82432209ef5c20526619b76a302`).

The helper hash after this patch is `5a1ec054f9b0406f7b8a5d47b79e259f14c2632089e0b08a922fd4c2ab447f22`. A separate source-current replay preserves all previous evidence and reuses the same four reference spectra and starts, plus the fifth stress spectrum's frozen native Betty seed and starts. Its manifest is `production_guard_replay/manifest.json`, SHA256 `522d6c1b47af4e6ebf99a7e83683b1b8d2d2cc88679a2898d2b33a527e61e152`; Slurm array 10855480 permits at most four simultaneous one-CPU jobs and ten minutes per case. It compares 192 reference endpoints and 48 prior stress endpoints under the original fixed tolerances and production budgets, with full fits saved before post-fit assertions. This is source-compatibility verification, not independent scientific confirmation.

The final guard replay completed all five cases and ten method problems, with all 240 planned stages retained and finite and no censoring or candidate exceptions. All 240 endpoints reproduced their archived counterparts within the fixed tolerances, including identical optimizer status, iteration counts, and evaluation counts: 192 reference comparisons and 48 separately scoped stress comparisons. All ten selected endpoints converged by relative objective reduction and passed the finite-neighborhood probes; nine passed distinct-origin agreement. The 10 Mb case 20 moments failure and the stress moments borderline improvement of 9.912352106766775e-05 remain unchanged. All five Slurm tasks completed with exit code 0:0 in 1m19s to 4m37s. The source-current audit is `production_guard_replay/summary.json`; original replay and retry records remain separate and unchanged.

The final integration snapshot passed 1,089 tests on macOS, Linux ARM, and Betty (38.27, 50.49, and 192.81 seconds, respectively; Betty job 10855604). The integration review verified the same 465 source hashes and 827 fixture hashes on all three platforms, and Ruff passed. Together with the retained failures, independent source reviews, and the source-current endpoint replay, this supports merging the bounded numerical mitigation. It does not certify every fit, biological recovery, interval coverage, or submission readiness.

## Reproduction

The manifest and copied inputs are frozen before submission. On Betty, run `sbatch --array=0-4%4 run.sbatch` from the replay directory; the script selects the archived production source snapshot. Re-running requires a separate results destination because each case refuses existing output. To audit the final copied results with the matching source tree, run `PYTHONPATH=src:. python experiments/readiness_2026_11_20/bottleneck/production_guard_replay/summarize.py`. The original replay and retry retain their own frozen sources and summaries.

The pre-patch focused local suite passed 131 tests spanning the optimizer, retained trace and source contracts, bootstrap failure behavior, both numerical engines, data/projection compatibility, and downstream calibration consumers. Ruff passed on changed code and the replay scripts. An independent read-only review recorded the six resolved findings and exact source hashes in `experiments/readiness_2026_11_20/bottleneck/optimizer_cross_review.json` (SHA256 `4ba8b8af9051c3c38a1bbeef686b6e343fb438ed946c7ca76a9f1d5436e1e035`); it independently passed 41 consumer and 24 optimizer regressions without reading replay outcomes or truth. Whole-repository and cross-platform integration are reported separately by the integration review.
